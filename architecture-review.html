Small interface hides projection, ingest, and ledger
Problem

The hydration seam between wt-cli and wt-store is shallow, leaking lockfile heuristics, sidecar ledger writing, mirror publishing, and 19 unpacked parameters across crate borders.

Solution

Deepen DiskStore::hydrate to encapsulate the entire projection lifecycle behind one small interface accepting source path, destination path, and hydration options.

Wins
  • ✓ leverage: interface shrinks by 15 parameters
  • ✓ locality: storage ledger stays in store
  • ✓ locality: mirror publishing stays in store
  • ✓ tests hit one complete seam
  • ✓ implementation absorbs 180 lines in cli

WorkspaceEngine owns git lifecycle; store owns metadata
Problem

The worktree retirement seam is inverted: StoreReclaimer deletes git worktrees via a hypothetical one-adapter trait (WorkspaceCleaner) calling back into wt-cli, while four commands hand-roll divergent removal sequences.

Solution

Deepen WorkspaceEngine to own the full worktree retirement and rollback lifecycle, calling the store across a clean seam only to unclaim references and mirrors.

Wins
  • ✓ delete hypothetical trait with one adapter
  • ✓ locality: git mechanics concentrate in workspace
  • ✓ leverage: one retirement interface for all
  • ✓ eliminates circular cross-crate call cycle
  • ✓ rollback and cleanup share implementation

Worth exploring in-process

After: Deep Batch Materializer
wt-store::hydrate
Passes file batch slice across the seam
wt-copy::Materializer (Deep Module)
Encapsulates thread pool, worker loops, atomic task distribution, mode normalization, and outcome aggregation behind one method
Concurrency and copy fallbacks concentrate in wt-copy
Problem

wt-copy::Materializer provides only a single-file interface, forcing wt-store to hand-roll 70 lines of thread pool orchestration, worker scoping, atomic counters, and error slots.

Solution

Deepen wt-copy::Materializer with a batch materialization interface that encapsulates thread worker scaling, task distribution, and error aggregation.

Wins
  • ✓ locality: thread pooling moves to copy
  • ✓ leverage: batch placement reusable across store
  • ✓ interface hides 70 lines of concurrency
  • ✓ concurrent placement testable in isolation

Worth exploring in-process

Primitive obsession: callers coordinate 6 parallel lookups
After: Single Structured Domain Manifest
Manifest (Canonical Domain Model)
entries: Vec<SnapshotEntry>
• SnapshotEntry::File(blob, mode, size) • Symlink(target) • Dir(mode)
Illegal states unrepresentable; zero reconstruction cost
Problem

Tree ingestion decomposes directory metadata into six parallel disjoint maps and vectors in Ingested, forcing downstream modules to coordinate parallel lookups and reconstruct SnapshotEntry instances.

Solution

Deepen the tree ingestion module to construct and return a canonical Manifest directly, embedding normalized modes and content addresses in a single indexed domain model.

Wins
  • ✓ domain model eliminates 6 parallel collections
  • ✓ illegal states become completely unrepresentable
  • ✓ locality: entry normalization happens at ingest
  • ✓ leverage: manifest feeds downstream projection directly
